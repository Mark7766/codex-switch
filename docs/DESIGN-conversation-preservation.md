# DESIGN: 对话历史保护方案

- **日期**：2026-06-14
- **状态**：📋 待 Review
- **优先级**：P0（多用户反馈）
- **目标版本**：v1.9.0

---

## 1. 问题全景

经过完整根因分析，用户反馈"历史对话记录没有了"由三个独立问题叠加导致：

```
┌─────────────────────────────────────────────────────────────┐
│ 问题 1: 代理重启不刷盘                                       │
│   触发: 改设置→重启代理→最近 5 秒的对话未写入磁盘              │
│   影响: 少量近期对话永久丢失                                   │
├─────────────────────────────────────────────────────────────┤
│ 问题 2: 过期清理过于激进                                      │
│   触发: 24h 未访问自动删除 + 最多保留 50 条                    │
│   影响: 跨天使用或对话多的用户历史被静默清除                    │
├─────────────────────────────────────────────────────────────┤
│ 问题 3: 服务器切换造成"假性丢失"                               │
│   触发: base_url 从 api.openai.com → 127.0.0.1:11435         │
│   影响: 对话在 OpenAI 服务器上完好，但 Codex Desktop UI 不可见  │
│   占比: 用户反馈的大多数（没丢，只是找不到了）                   │
└─────────────────────────────────────────────────────────────┘
```

---

## 2. 解决方案

### 措施 ①：代理停止前强制刷盘（修复问题 1）

**位置**：`electron/proxy/server.ts` — `stopInternal()` 和 `electron/main.ts` — `before-quit`

**改动**：

```
stopInternal() 流程改为:
  1. await this.conversationStore.forceFlush()  ← 新增：先刷盘
  2. 终止 WS 连接
  3. 关闭 HTTP 连接
  4. 关闭 Server

before-quit 流程改为:
  1. track('app_close')
  2. await conversationStore.forceFlush()       ← 新增
  3. await telemetry.stop()
  4. proxy.stop()
```

**效果**：代理重启、退出、崩溃恢复时，对话数据 100% 落盘后再停，零丢失窗口。

---

### 措施 ②：保留策略交给用户控制（修复问题 2）

**核心原则**：用户的数据，用户做主。不清除、不静默、让用户看见、让用户选择。

**位置**：`electron/proxy/conversation-store.ts` + `electron/config/store.ts` + `src/pages/Settings.tsx`

#### 2a. 默认不清除，只做兜底保护

| 参数             | 当前值         | 新值                                   | 说明                         |
| ---------------- | -------------- | -------------------------------------- | ---------------------------- |
| `MAX_AGE_MS`     | 24h（自动删）  | 取消（不按时间清理）                   | —                            |
| `MAX_ENTRIES`    | 50（自动删）   | **1000**（默认值，用户可在设置中修改） | 仅作极端兜底，正常永远到不了 |
| 到达上限时的行为 | 静默删除最旧的 | **弹窗告知用户，让用户选择**           | 参见 2b                      |

#### 2b. Settings 新增「对话缓存」配置区块

```
┌──────────────────────────────────────────────────────────┐
│  对话缓存                                                  │
│                                                          │
│  当前状态                                                 │
│  ┌──────────────────────────────────────────────────┐    │
│  │ 已缓存 47 条对话记录    占用约 2.3 MB 磁盘空间      │    │
│  │ 最早记录：2026-06-11                               │    │
│  └──────────────────────────────────────────────────┘    │
│                                                          │
│  缓存上限                                          [1000] │
│  ┌──────────────────────────────────────────────────┐    │
│  │ 达到上限时，自动保留最近 N 条，删除最早的。        │    │
│  │ 对话内容同时保存在 Codex Desktop 中，              │    │
│  │ 清空缓存不会丢失历史对话。                        │    │
│  └──────────────────────────────────────────────────┘    │
│                                                          │
│                                        [清空全部缓存]     │
└──────────────────────────────────────────────────────────┘
```

**关键行为**：

- **默认 1000**，用户可修改（范围 100–10000）
- 到达上限时，**弹窗告知**，不静默删除：

```
┌──────────────────────────────────────────────────────────┐
│  ⚠️ 对话缓存已满                                          │
│                                                          │
│  当前缓存了 1000 条对话记录，已达到上限。                  │
│  最早缓存的 500 条记录将被自动清理。                       │
│                                                          │
│  对话内容同时保存在 Codex Desktop 中，                    │
│  清空缓存不会丢失任何历史对话。                            │
│                                                          │
│  你可以在设置中调整缓存上限。                              │
│                                                          │
│            [去设置调整]   [清理最早 500 条]   [暂时不清理]   │
└──────────────────────────────────────────────────────────┘
```

- 三个按钮让用户选择：调整上限 / 清理继续 / 暂不处理

#### 2c. 关于对话归档

Codex Desktop 的"归档"功能是将对话从活跃列表移到 `archived_sessions/` 目录。这个操作**对 conversation-store 完全透明**：

- Codex Desktop 归档对话时，对话的 `previous_response_id` 仍然有效
- 用户从归档中恢复对话继续聊天时，proxy 正常从 store 恢复历史
- conversation-store **本身不需要支持归档**——它就是个缓存，不区分活跃/归档

**codex-switch 不需要实现归档功能**——那是 Codex Desktop 的事。我们只需要保证缓存里对应的记录不被错误清理（措施 ② 已解决）。

### 措施 ③：对话记录来源切换（修复问题 3）

**核心思路**：对话只存在两个地方——OpenAI 服务器 或 Codex Switch 代理。不需要备份列表，只需要一个开关。

#### 3a. Settings 新增「对话记录来源」开关

**位置**：`src/pages/Settings.tsx` + `electron/codex/writer.ts`

备份列表的问题：用户不知道哪个备份对应什么，时间戳看不懂。实际上只有两种状态：

| 状态              | config.toml base_url        | 对话在哪          |
| ----------------- | --------------------------- | ----------------- |
| OpenAI 官方       | `https://api.openai.com/v1` | OpenAI 服务器     |
| Codex Switch 代理 | `http://127.0.0.1:11435/v1` | Codex Switch 代理 |

用一个开关直观表达：

```
┌──────────────────────────────────────────────────────────┐
│  对话记录来源                                             │
│                                                          │
│  ┌──────────────────────────────────────────────────┐    │
│  │  ● Codex Switch 代理（当前）                       │    │
│  │    新对话通过 DeepSeek，享受免费/低成本推理          │    │
│  │                                                   │    │
│  │  ○ OpenAI 官方                                     │    │
│  │    使用安装前的原始配置，找回之前的 OpenAI 对话       │    │
│  │    注意：切换到 OpenAI 后需使用 OpenAI API Key       │    │
│  └──────────────────────────────────────────────────┘    │
│                                                          │
│                        [切换到 OpenAI 官方]                │
│                                                          │
│  ℹ️ 切换不会删除任何对话——只是在两个存储位置之间切换。      │
│  之前的对话始终完好保存在原来的服务器上。                  │
└──────────────────────────────────────────────────────────┘
```

**按钮行为**：

| 当前状态    | 按钮文字                   | 点击后                                           |
| ----------- | -------------------------- | ------------------------------------------------ |
| 代理模式    | "切换到 OpenAI 官方"       | 还原首次安装时备份的 config.toml + auth.json     |
| OpenAI 模式 | "切换到 Codex Switch 代理" | 重新写入代理配置（当前端口、模型、DeepSeek Key） |

**实现要点**：

- 只在**存在原始备份**时显示此区块（即用户是先有 Codex Desktop 再装 codex-switch）
- 切换时先备份当前配置，再还原目标配置
- 切换后弹出 toast："已切换到 XXX，重启 Codex Desktop 后生效"
- 每次切换自动备份对方配置，所以可以反复来回切

#### 3b. 备份策略简化

**位置**：`electron/codex/writer.ts`

当前问题：prune 最多保留 5 份，滚动时可能把首次备份也删了。

改为：

```
备份分为两类:
  1. 原始备份（install-original）: 首次安装时生成，永久保留，不参与滚动
  2. 常规备份（.bak.<timestamp>）:  每次配置变更时生成，保留最近 5 份

pruneBackups 跳过标记为 install-original 的文件
```

**备份文件命名**：

- 原始备份：`config.toml.bak.install-original`
- 常规备份：`config.toml.bak.1781357184619`（不变）

#### 3c. Setup 向导增加对话提示

**位置**：`src/pages/Setup.tsx` — 完成页面

在最后一步"完成并启动代理"旁边，增加信息块：

```
┌─────────────────────────────────────────────────────────┐
│  ℹ️ 关于之前的对话记录                                    │
│                                                         │

│  你可以在 设置 → 对话记录来源 中随时切换回去查看。         │
└─────────────────────────────────────────────────────────┘
```

## 4. 边界情况

| 场景                                     | 处理                                                                     |
| ---------------------------------------- | ------------------------------------------------------------------------ |
| 用户从未安装过 Codex Desktop（无旧对话） | Setup 向导不显示提示（无备份文件时不显示）                               |
| 用户卸载后重装 codex-switch              | 新备份覆盖旧备份？不——用 `Date.now()` 做后缀，不会冲突                   |
| 用户手动删除备份文件                     | Settings 列表为空，提示消失                                              |
| 代理崩溃（非正常 stop）                  | before-quit 兜底；崩溃场景无法 100% 保证，但正常退出和重启全覆盖         |
| 对话内容本身超大（单条 > 10MB）          | 不处理——Codex 协议本身不支持单条超大消息                                 |
| conversation-store.ndjson 文件损坏       | `load()` 已做 corrupt line skip，不会崩溃但部分数据丢失                  |
| 用户误点清空缓存                         | 二次确认弹窗："确定清空？对话在 Codex Desktop 本地仍有保存"              |
| 缓存文件过大（> 100MB）                  | Settings 显示占用，用户可手动清理；极端情况自动截断最早 50% 条目         |
| Codex Desktop 归档对话                   | 不处理——归档不影响 previous_response_id 有效性，从归档恢复后缓存照常工作 |
| 用户修改缓存上限为极小值                 | 输入校验：最小 100，小于当前缓存数时提示"需要先清理 X 条"                |

---

## 5. 不做的事项

| 事项                       | 原因                                            |
| -------------------------- | ----------------------------------------------- |
| 自动迁移 OpenAI 对话到本地 | Codex Desktop 不提供对话导出/导入 API，无法实现 |
| 备份加密                   | 当前明文备份已满足"找回"需求；加密增加复杂度    |
| 定时自动备份               | 当前每次写入自动备份，已满足需求                |
| 云端备份                   | 超出本地桌面工具的范围                          |
